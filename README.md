# Клиент для эмбеддинг-API (mock) с обработкой ошибок

- Используемый язык - Python 3.  
- Рабочая директория - src. Вести работу внутри нее.  

# Подготовка

Виртуальное окружение Venv уже создано внутри директории src - создавать его с нуля не нужно  

**Запустить виртуальное окружение venv**  
`source .venv/Scripts/activate`  

**Загрузить и установить библиотеки**  
`pip install -r requirements.txt`  

# Вспомогательные команды и флаги (использовались при разработке)

**Создать виртуальное окружение Python**  
`python -m venv .venv`

`where python`

`which python`  
Выведет тот путь, который используется сейчас

`(.venv)`

`pip freeze`

# Как поднять сервер

`python mock_embedding_api.py`

`http://127.0.0.1:8000/docs`  
Это приведет нас на страницу, где можно протестировать эндпоинт POST с помощью графического интерфейса

# Как выключить сервер

Используем ту сессию терминала, в которой поднимали сервер  
`Ctrl + C`

# Как запустить клиент

**Вызов справки**  
`python embedding_client.py --help`  

**Необязательные аргументы командной строки - конфигурация**  
`--text`          Текст запроса к серверу  
`--max_retries`   Максимальное количество повторных попыток  
`--start_delay`   Начальная задержка между попытками  
`--multiplier`    Множитель задержки  

**Значения параметров по умолчанию (используются при запуске без конфигурации)**  
`--text`          Hello World  
`--max_retries`   3  
`--start_delay`   0.01  
`--multiplier`    2.0  

**Запуск без конфигурации**  
`python embedding_client.py`  

**Запуск с конфигурацией**  
`python embedding_client.py --text test_404 --max_retries 5 --start_delay 0.01 --multiplier 3.0`  

# Как запустить тесты

`pytest`  
Все тесты будут запущены автоматически, прописывать каждый из них по отдельности не требуется  

# Стратегия повторных попыток

`--max_retries`   3  
`--start_delay`   0.01  
`--multiplier`    2.0  

Количество повторных попыток выбрано в соответствии с рекомендациями.  
Начальная задержка выбрана заведомо маленькой для ускорения тестов.  
Множитель выбран минимальным для ускорения тестов.  
Данная стратегия обеспечивает оптимальное соотношение между вероятностью успешного ответа сервера и скоростью выполнения.

# Сравнение с альтернативами

| Реализация | Скорость и результаты | Примечания |
| :---: | :---: | :---: |
|**Стандартная конфигурация на ручной реализации** | Средняя скорость, высокие результаты | Нужно писать самостоятельно, трудно поддерживать |
|**Альтернативная конфигурация на ручной реализации** | Низкая скорость, средние результаты | Нужно писать самостоятельно, трудно поддерживать, хуже стандартной |
|**Стандартная конфигурация на tenacity** | Средняя скорость, высокие результаты | Готовая библиотека, легко поддерживать, трудно изучать, зависимость от библиотеки |
|**Конфигурация без повторов на ручной реализации** | Высокая скорость, плохие результаты | Нужно писать самостоятельно, трудно поддерживать, хуже альтернатив |

**Вывод**  
Стандартная конфигурация с ручной реализацией и стандартная конфигурация на tenacity работают примерно ОДИНАКОВО.  
Можно использовать и то, и другое. Чтобы не изобретать велосипед, лучше использовать tenacity.  

# Статусы ошибок

**Временные ошибки**  

1) Ошибка 429 Too Many Requests: ошибка на стороне клиента, может исчезнуть со временем
2) Ошибка 500 Internal Server Error: ошибка на стороне сервера, может исчезнуть со временем
3) Ошибка 503 Service Unavailable: ошибка на стороне сервера, может исчезнуть со временем
4) TimeOut: может исчезнуть при следующих запросах

**Постоянные ошибки**  
1) Ошибка 400 Bad Request: ошибка на стороне клиента (некорректный запрос), не исчезнет при повторной попытке
2) Ошибка 404 Not Found: ошибка на стороне клиента (некорректный URL), не исчезнет при повторной попытке
